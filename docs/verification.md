- CLI `close` 后网页窗口移除；网页打开计算器后 CLI 列表立即出现对应会话。
- 已验证编译后的 CLI 读取设备、打开应用；Chrome 地址栏中文写入及读取成功，计算器键盘输入和软键盘开关同步成功。

## 文件摄像头

- 实际 Android Chrome 完整链路：本机循环二维码视频 → 960 × 1280 虚拟摄像头 → `getUserMedia()` → `BarcodeDetector`，成功读取 `WEBADB-FILE-CAMERA-TEST`。
- 换内容验收：浏览器时钟画布持续生成当前时间、毫秒、帧号、移动标记和另一二维码，Android Chrome 相机中看到时间从 00:58:34 更新到 00:58:40、00:58:59，并成功识别 `WEBADB-LIVE-CLOCK-960x1280`。这证明应用读到持续变化的画面，且来源确实切换。
- 正式来源为图片、视频、媒体链接三种，均由后端持有。时钟 HTML 是额外的前台画布验收工具，不属于正式后台来源。
- 已在手机连接状态下通过 CLI 实测本机 PNG、循环 MP4、HTTP 图片 / 视频、RTSP、HLS、RTMP。媒体服务仅绑定本机，测试无需再次解除手机相机隐私保护。
- CLI 命令返回后后台继续供帧；HTTP MP4 超过原始时长反复播放。暂停时确认帧数不再增长，恢复后继续。
- 链接类型必须明确选择图片、视频或实时视频流，网页未选类型时不能开始，CLI 缺少 `--kind` 返回非零，API 缺少类型返回 400；已验证选择实时视频流后 RTSP 推流成功。
- 最终网页验收：图片、视频、媒体链接依次开始 / 切换成功，CLI 返回相同来源；CLI 暂停会同步显示网页“已暂停”，网页恢复后 CLI 返回 `paused: false`。
- 导航离开 WebADB 后，CLI 确认帧数从 254 增至 419；重新打开网页确认 877 帧及同一来源。CLI 停止后网页立即显示“未推流”。
- 浏览器预览为 240 × 320（3:4）；390 × 844 视口的文档宽度为 390，没有横向溢出。三个推流按钮高 40 px、同一纵坐标；桌面布局也已截图检查。
- 选择文件和打开应用不会自动启动摄像头。实际送入手机的 JPEG 与 Android 前后相机声明均为 960 × 1280，helper 拒绝其他尺寸。
- 手动停止后伴生关联为空。修复开发服务重启时的临时 JAR / 伴生关联清理竞态，host 在 helper 关闭后再次精确清理本次资源。

真机验收依赖当前 Android 16 小米 ROM。不同目标扫码应用、其他 ROM、异常拔线场景仍需相应设备验证，不能据此承诺任意手机上的全局摄像头替换。后台媒体仅注入 WebADB 虚拟设备中的应用，不替换手机主屏应用的物理摄像头。

## 隐私恢复与清理

已确认小米隐身模式的 secure 设置与系统属性均为 1，Chrome 主设备 CAMERA 权限恢复为未授权、UID AppOps 为 ignore。手机主屏保持黑屏 / Dozing。每次会话只移除自己的临时 JAR、伴生关联、虚拟显示和 ADB reverse，不触碰其他调试会话；服务器正常退出后再次检查残留。

## v0.3.1 统一程序

- `awsl-webadb --help`、`--version`、`serve` 与原客户端命令共用同一个入口；端口越界、未知服务参数和端口占用均返回非零退出码。
- 已交叉编译 Linux amd64 / arm64 与 macOS amd64 / arm64 四份包含前端资源的二进制。本机只运行 macOS arm64；Intel 版本为有效 x86_64 Mach-O，但当前电脑没有对应执行环境，未宣称已运行验证。Linux amd64 的运行验证由发布 CI 完成。
- macOS arm64 二进制从空目录启动服务端，再用同一文件的客户端查询会话；核对全部 23 个内置文件与构建目录字节一致，包括网页、脚本、字体、scrcpy server 与手机 helper。非允许来源返回 403。
- 从临时空目录用统一程序连接 USB 手机，打开计算器成功；读取 159 个元素，保存 45,119 字节 JPEG 与 44,178 字节 XML，关闭会话和服务后伴生关联、临时 JAR 已释放，隐身模式保持开启。
- Homebrew Formula 使用四个平台的 SHA256SUMS 生成，Ruby 语法通过；临时放入本机现有 tap 后，Homebrew 元数据解析选中了 macOS arm64 地址、校验和、FFmpeg 依赖及正确的后台服务命令。测试后移除临时 Formula，未更改已安装应用或启动新的系统服务。
- 自动更新 tap 参考同组织 maxx 的流程，使用 `HOMEBREW_TAP_TOKEN`；尚未配置令牌时明确跳过并提供手动重跑入口，不能将其描述成已发布到 tap。
