## 文件摄像头

- 实际 Android Chrome 完整链路：本机循环二维码视频 → 960 × 1280 虚拟摄像头 → `getUserMedia()` → `BarcodeDetector`，成功读取 `WEBADB-FILE-CAMERA-TEST`。
- 换内容验收：浏览器时钟画布持续生成当前时间、毫秒、帧号、移动标记和另一二维码，Android Chrome 相机中看到时间从 00:58:34 更新到 00:58:40、00:58:59，并成功识别 `WEBADB-LIVE-CLOCK-960x1280`。这证明应用读到持续变化的画面，且来源确实切换。
- 正式来源为图片、视频、媒体链接三种，均由后端持有。时钟 HTML 是额外的前台画布验收工具，不属于正式后台来源。
- 已在手机连接状态下通过 CLI 实测本机 PNG、循环 MP4、HTTP 图片 / 视频、RTSP、HLS、RTMP。媒体服务仅绑定本机，测试无需再次解除手机相机隐私保护。
- CLI 命令返回后后台继续供帧；HTTP MP4 超过原始时长反复播放。暂停时确认帧数不再增长，恢复后继续。
- 链接类型必须明确选择图片、视频或实时视频流，网页未选类型时不能开始，CLI 缺少 `--kind` 返回非零，API 缺少类型返回 400；已验证选择实时视频流后 RTSP 推流成功。
- 最终网页验收：图片、视频、媒体链接依次开始 / 切换成功，CLI 返回相同来源；CLI 暂停会同步显示网页“已暂停”，网页恢复后 CLI 返回 `paused: false`。
- 导航离开 WebADB 后，CLI 确认帧数从 254 增至 419；重新打开网页确认 877 帧及同一来源。CLI 停止后网页立即显示“未推流”。
- 前期浏览器预览为 240 × 320（3:4）；原 3:4 面板调整为 220 × 293.3；新版预览按输出比例自适应。手机推流按钮至少高 44 px，同一纵坐标。
- 选择文件和打开应用不会自动启动摄像头。此前默认 JPEG 与 Android 前后相机声明为 960 × 1280；新版声明与帧校验改为本次选择的输出尺寸。
- 手动停止后伴生关联为空。修复开发服务重启时的临时 JAR / 伴生关联清理竞态，host 在 helper 关闭后再次精确清理本次资源。

真机验收依赖当前 Android 16 小米 ROM。不同目标扫码应用、其他 ROM、异常拔线场景仍需相应设备验证，不能据此承诺任意手机上的全局摄像头替换。后台媒体仅注入 WebADB 虚拟设备中的应用，不替换手机主屏应用的物理摄像头。
